## 2. Kết quả Phân tích Kỹ thuật Mã nguồn (Code Analysis)

### 2.1. Quản lý Giao dịch SQLite & Tính Bất biến (`store.py`)
1. **Kiểm soát Đường dẫn & Chống Traversal (`_resolve_data_root`):**
   - Giới hạn chặt chẽ dưới `data/public_search/`. Mọi đường dẫn tuyệt đối hoặc chứa `..` đều bị từ chối (`StoreError(kind="storage")`).
2. **Khởi tạo và Phòng chống Tự động Tái tạo Ngầm (`initialize_store` vs `open_existing`):**
   - `open_existing` không bao giờ tự tạo thư mục hay database mới nếu thiếu file hoặc thiếu marker (`store.json`).
   - `initialize_store` đảm bảo tính **Idempotent**: nạp marker, đối soát `config_sha256` và metadata của SQLite trước khi trả về `SQLiteStore`.
   - **Chống ghi đè khi hỏng DB (`_has_evidence`):** Thư mục có bằng chứng cũ nhưng thiếu DB hoặc hỏng marker thì **từ chối tự tái tạo**, ngăn chặn việc nuốt lỗi mất dữ liệu.
3. **Tính Nguyên tử của Raw Payload & Database Transaction (`save_snapshot`):**
   - **Raw Payload:** Đối soát 1:1 `raw_references` và `raw_payloads` (SHA-256 + byte count). Ghi atomic qua `tempfile.mkstemp` + `os.replace`. Cấm thay đổi raw ID đã tồn tại với nội dung khác (`"raw id immutable different bytes"`).
   - **Database Transaction:** Khóa ghi bằng `BEGIN IMMEDIATE`. Con trỏ `cache` **chỉ dịch chuyển** khi `overall` đạt `"success"` hoặc `"empty"`. Snapshot `"partial_failure"` hoặc `"failed"` giữ nguyên 100% con trỏ cache cũ.
4. **Lưu Thư viện Idempotent (`save_paper`):**
   - Xác thực `canonical_id` bắt buộc phải tồn tại trong `fusion.hits`.
   - Transaction `BEGIN IMMEDIATE` kiểm tra `SELECT entry_json FROM library WHERE canonical_id = ?`. Trả về đúng `LibraryEntry` hiện có mà không ghi đè, không thay đổi timestamp `saved_at` ban đầu.

### 2.2. Kiểm soát Cache, TTL, Trạng thái Cũ (Stale) & Toàn vẹn Băm (`load_cache`, `read_snapshot`)
1. **Anti-Silent-Bypass trong `load_cache`:**
   - Khi tìm thấy cache key trong SQLite, `load_cache` chủ động **kiểm tra toàn bộ raw references trên đĩa** (sự tồn tại, hash SHA-256, byte count).
   - Nếu file raw hoặc snapshot bị hỏng/xóa, hàm **lập tức ném `StoreError`**, tuyệt đối **không trả về `None`** và không fallback ngầm che giấu lỗi.
   - Kiểm tra TTL chuẩn xác: chỉ trả về snapshot khi dữ liệu toàn vẹn và `now < snapshot.expires_at`; nếu hết hạn TTL (`now >= snapshot.expires_at`), trả về `None` hợp lệ.
2. **Đọc Snapshot cũ (`read_snapshot`):**
   - Cho phép người dùng truy xuất lại các snapshot cũ (kể cả hết hạn TTL hoặc snapshot lỗi một phần) theo `snapshot_id`, đồng thời vẫn kiểm tra toàn vẹn băm raw payload tương ứng.

### 2.3. Quy tắc Thoát ký tự BibTeX & Xuất Thư viện (`export.py`)
1. **Thoát ký tự đặc biệt BibTeX (`bibtex_escape`):**
   - Chuyển `\r\n`, `\n`, `\r`, `\t` sang khoảng trắng đơn.
   - Thoát đầy đủ: `\` -> `{\textbackslash}`, `{` -> `\{`, `}` -> `\}`, `#` -> `\#`, `$` -> `\$`, `%` -> `\%`, `&` -> `\&`, `_` -> `\_`, `^` -> `{\textasciicircum}`, `~` -> `{\textasciitilde}`.
2. **Khóa BibTeX ổn định (`stable_bibtex_key`):**
   - Chuẩn hóa canonical ID thành chuỗi ký tự an toàn ASCII (`A-Za-z0-9_:-`), thêm tiền tố `paper_` nếu bắt đầu bằng chữ số, giới hạn tối đa 64 ký tự.
   - Giải quyết xung đột trùng khóa bằng cách thêm hậu tố `_2`, `_3`... đảm bảo tổng chiều dài `<= 64`.
3. **Tiêu chuẩn Kỹ thuật Xuất dữ liệu:**

   - `export_bibtex` sắp xếp theo `e.canonical_id`, ghi nhận nguồn gốc snapshot và cờ `incomplete:true/false` vào trường `note`.

### Finding EXT07M-F01 (Severity: P2 - Vận hành / Giới hạn Mục tiêu Hiệu năng Cache)
- **Vị trí:** `artifacts/reports/public_search/muse/pilot-recovery-102.json:1540,1577`
