## Findings cần sửa

### F1 — P1 — Error message có thể đưa credential vào exception/log

- Vị trí: `src/scholargraph/ingest/openalex.py:617–625`, được sử dụng tại nhánh HTTP lỗi không retry ở `_fetch_page()`.
- `_safe_error_message()` trả nguyên `message`/`error` từ response, chỉ cắt 300 ký tự. Dù request gửi key qua header, lỗi server/proxy phản chiếu header hoặc token sẽ đi nguyên vào `OpenAlexAPIError`; CLI không bắt exception nên traceback chứa nó. Đây là đường xuất log chưa có secret guard.
- Tái hiện trong bộ nhớ: fake client trả HTTP 401 với `{"message": "Invalid Bearer " + secret}`; truyền cùng chuỗi **synthetic** làm `api_key`, gọi `_fetch_page(1)` rồi kiểm `secret in str(exception)`. Kết quả **True**. Không dùng hay phát hiện credential thật bị lộ trong snapshot hiện tại.
- Cần sanitize trước khi tạo exception: che exact credential, Bearer/API-key/query-token patterns; hoặc chỉ xuất mã lỗi an toàn. Kiểm cả JSON error lồng nhau; thêm regression test cho error echo và xác nhận traceback/log không còn secret. Test hiện tại chỉ kiểm output của nhánh 429→500→200 nên bỏ sót đường này.

### F2 — P2 — Retry-After bị rút ngắn bởi trần backoff

- Vị trí: `src/scholargraph/ingest/openalex.py:267–280` và `629–636`.
- Code tính `min(max_backoff_seconds, max(retry_after, exponential_backoff))`. Với giá trị mặc định, server yêu cầu chờ 120 giây nhưng client gửi lại sau 60 giây. Nếu hạn mức chưa reset, các lượt retry tiếp tục bị từ chối và có thể hết retry dù downloader được gọi đúng.
- Tái hiện: fake response HTTP 429, header `Retry-After: 120`, sau đó 200; sleeper chỉ ghi số giây vào list. Kết quả **`[60.0]`**. Header HTTP-date hợp lệ cũng bị `_parse_retry_after()` biến thành `0.0`.
- Cần dùng thời gian server yêu cầu làm cận dưới, chỉ cap phần exponential backoff; nếu không thể đợi lâu, dừng có checkpoint và thông tin resume thay vì retry sớm. Hỗ trợ HTTP-date và thêm tests cho delay lớn hơn cap/date/quota reset.
- Căn cứ: [OpenAlex error handling](https://help.openalex.org/api/errors/) yêu cầu chờ khi 429/quota cạn; [RFC 9110 §10.2.3](https://www.rfc-editor.org/rfc/rfc9110.html#name-retry-after) định nghĩa Retry-After dạng số giây hoặc HTTP-date.
